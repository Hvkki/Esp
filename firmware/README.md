# Прошивка: HF-link інвертор на ESP32 / ESP32-S3

## Попередження

Цей код керує силовою частиною, здатною розсіяти кіловати за мілісекунди. Він **не має**
жодного програмного захисту, який можна вважати достатнім. Єдиний захист, на який можна
покладатися, — **зовнішній аналоговий компаратор струму**, підключений до `GPIO_FAULT_N`.
Він вимикає виходи MCPWM апаратно (режим OST), без участі процесора.

Не підключати до акумулятора без цього компаратора. Період носія 70 кГц = 14 мкс;
ADC ESP32 працює ~2 мкс на вибірку і не має ні детермінізму, ні hardware trip-zone,
тому програмний захист по струму тут фізично не встигає.

`INV_DUTY_MAX_Q15` за замовчуванням обмежений на ~12%. Підіймати тільки після перевірки
осцилографом.

## Апаратна платформа

| Вимога | Значення |
|---|---|
| Чіп | **ESP32 або ESP32-S3** |
| Чому не S2 | ESP32-S2 не має блоку MCPWM — код не збереться |
| MCPWM | 2 блоки × 3 таймери × 3 оператори (6 виходів на блок) |
| Такт групи | до 160 МГц → крок фази 6.25 нс |
| ESP-IDF | v5.x (використовується `driver/mcpwm_prelude.h`) |

Розподіл ресурсів:

| Блок | Призначення | Виходів |
|---|---|---|
| MCPWM0 | LV phase-shift full bridge (2 плеча з мертвим часом) | 4 |
| MCPWM1 | синхронний випрямляч (2 плеча з мертвим часом) | 4 |
| GPIO | unfolder (працює на частоті виходу 20–400 Гц) | 2 |

## Форма сигналів

Період T, фазовий зсув `phi` у діапазоні `[0, T/2]`:

```
LV плече A:  HI від 0 до T/2                       (ведуче, фіксоване)
LV плече B:  HI від phi до phi + T/2               (ведене, зсув = потужність)
             -> первинка: +V на [0, phi), -V на [T/2, T/2+phi)
             -> duty = 2*phi/T, і phi ніколи не перетікає межу періоду

SR плече 1:  HI від 0 до (phi - trail)
SR плече 2:  HI від (T/2 + lead) до (T/2 + phi - trail)
             -> коли обидва LO, замкнені нижні ключі SR -> freewheel дроселя
             -> тому unfolder комутує лише на 50 Гц, а не на частоті носія
```

Комплементарні пари формує апаратний dead-time модуль MCPWM.

## Синхронізація двох блоків MCPWM

Обидві групи тактуються від одного PLL_160M і мають однаковий період, тому достатньо
одноразового вирівнювання програмним синхросигналом (`inv_pwm_start`). Але два записи
в регістри не відбуваються в один такт, тому **залишковий зсув у кілька тіків треба один
раз виміряти осцилографом** і скомпенсувати константами `INV_SR_LEAD_TICKS` /
`INV_SR_TRAIL_TICKS`.

## Що НЕ реалізовано (і потрібно до роботи на потужності)

- зворотний звʼязок по вихідній напрузі та струму (тут розімкнена петля);
- адаптивне підстроювання вікон SR по Vds — це має бути аналоговий контур,
  бо вікно провідності змінюється щоцикла разом з duty і leakage;
- контроль температури, precharge вхідного банку, контроль напруги пака, звʼязок з BMS;
- виявлення реактивного навантаження (для cos φ ≠ 1 проста схема SR + unfolder
  не працює — див. `docs/REVIEW.md`, п.7).

## Порядок першого запуску

1. **Без силової частини.** Прошити, подивитися осцилографом усі 8 швидких виходів:
   правильні мертві часи, немає перекриття в плечі, вікна SR всередині вікон первинки.
2. Виміряти залишковий зсув між MCPWM0 і MCPWM1, скорегувати `INV_SR_LEAD/TRAIL_TICKS`.
3. **Драйвери без силових ключів.** Перевірити амплітуду і форму на затворах,
   від'ємне зміщення, роботу `GPIO_DRV_ENABLE`.
4. **Перевірити захист.** Замкнути `GPIO_FAULT_N` на масу під час роботи — усі виходи
   мусять впасти в нуль негайно і не піднятися самі.
5. **Лабораторний БЖ, 12 В, обмеження струму 2 А**, замість акумулятора. Навантаження —
   лампа розжарювання. duty підіймати з 5% вручну, дивлячись на струм і форму на первинці.
6. Тільки після цього — підвищення напруги, потім потужності, з тепловізором.

## Збірка

```
cd firmware
idf.py set-target esp32s3
idf.py build flash monitor
```

Якщо IDF не приймає `resolution_hz = 160000000` для MCPWM, знизити до 80 МГц
і відповідно перерахувати `INV_MCPWM_CLK_HZ` (крок фази стане 12.5 нс — цього все ще
достатньо для мертвих часів 40–60 нс).

## Стан

Код **не компілювався** — у пісочниці немає ESP-IDF. Це робочий скелет, який очікує
першої збірки на реальному оточенні; можливі дрібні розбіжності в іменах полів структур
між мінорними версіями ESP-IDF v5.x.
