# Executable inverter-loss correction gates remain bypassable (final review)

The full executable suite reports PASS, but adversarial probes found mandatory gates that accept fabricated or unbound inputs. The acceptance result therefore does not establish the requirements/design/tasks contract. Missing external evidence remains explicit in the generated report, yet several public APIs can still promote caller-created substitutes to available results.

**Watch for:** **confirmed BLOCKING** comparison artifacts authorize progression without required prerequisites; **confirmed BLOCKING** preservation never compares baseline behavior with the corrected implementation; **confirmed HIGH** timing actuals and expectations share one constructor; **confirmed HIGH** thermal/no-load inputs bypass validated evidence; **confirmed BLOCKING** fabricated qualification/control/publication claims become available; **confirmed HIGH** incomplete freshness graphs permit stale transitive consumption.

**Verdict**: NEEDS_CHANGES

## High-level view

**Confirmed BLOCKING:** comparison ineligibility validation covers only part of the prerequisite record. Stripped controlled inputs and unrelated endpoint evidence/policy/fixed-input hashes both produced empty diagnostics and valid progression authorizations.

**Confirmed BLOCKING:** the preservation runner executes frozen baseline artifacts but never the corrected implementation for `BASELINE_BEHAVIOR`. Its threefold case computes expected and actual with the same local expression, so all 72 evaluated cases can pass without preserving production behavior.

**Confirmed HIGH:** timing actuals and expectations both come from the compatibility `digital_oracle` saved at import time. Literal data checks selected scalars and counts, not the complete independent event vectors required by the contract.

**Confirmed HIGH:** thermal calculations accept inputs not bound to their hashed artifact, while no-load reporting trusts a caller-provided `SETTLED` label. These paths can publish stronger state than their evidence establishes.

**Confirmed BLOCKING:** qualification and control validate hash-reference shape rather than referenced content, and publication checks only presence for most semantic fields. Invented evidence can therefore become real qualification, `VERIFIED` status, and an available publication.

**Confirmed HIGH:** freshness checks do not validate completeness of the dependency graph. Missing transitive edges leave downstream results fresh and consumable after an upstream change.

## Fabricated ineligibility outcomes authorize realistic comparison

**Confirmed BLOCKING.** In `inverter_corrections.py:1796-1822`, `_validate_controlled_outcome` recalculates completed outcomes, but its ineligibility path only decodes `irms_bits`, reads `conduction_nonempty`, and checks the resulting code. It does not validate the input key set, positive resistance/parallel count, common temperature, waveform/timing/non-RDS hashes, or remaining requirement-2.29 prerequisites. A controlled outcome stripped to those two inputs passed with no diagnostic and returned valid authorizations.

At `inverter_corrections.py:1824-1854`, the endpoint path only requires several fields to look like SHA-256 values. Replacing `endpoint_evidence_hash`, `policy_hash`, and `fixed_input_hash` with hashes of unrelated strings still authorized progression. Both validators must derive prerequisites from registered content, not self-described hash fields.

## Preservation coverage does not execute corrected baseline behavior

**Confirmed BLOCKING.** `inverter_corrections_preservation_enforced.py:24-62` builds every `BASELINE_BEHAVIOR` case from `git show` data at the frozen commit. Its baseline branch calls no corrected production API; the conduction case assigns `expected` and `actual` using the identical local `Irms²×2×RDS/m` expression.

The acceptance gate treats these reports as semantic preservation, so a production regression can evade this component. Frozen eligible inputs must execute through both the immutable baseline adapter and current implementation; `NO_BASELINE_BEHAVIOR` routes also need behavior-specific assertions rather than schema-field presence.

## Expected and actual timing events share the compatibility constructor

**Confirmed HIGH.** The import-time assignment at `inverter_corrections.py:1453` saves the earlier `digital_oracle` as `_legacy_digital_oracle`. Both `compute_timing_from_firmware` at line 1444 and `independent_expected_timing` at line 1463 call it; probes confirmed all p=10/1/0 raw and adjusted vectors originate at source line 536. `_EXPECTED_TIMING` independently checks q, k, comparator values, intervals, and an adjusted count, but complete event identity/class/tick/order, unavailable fields, and residual ownership share implementation logic.

This is the real binding bypass among the duplicate definitions. Other strengthened overrides are reached through module-global lookup and have no captured default or registry aliases. Expected vectors must be constructed without `_legacy_digital_oracle`, while actuals are derived separately from firmware semantics.

## Thermal and no-load evidence can be bypassed by caller state

**Confirmed HIGH.** `thermal_transient` validates a method artifact hash, then computes with separately supplied temperatures, domains, Cth, Rth, and elapsed time without binding them to artifact content or result dependencies. A hashed artifact declaring network values of 1 accepted caller Cth/Rth values of 999 and returned `AVAILABLE`.

At `inverter_corrections.py:1525`, `no_load_report` accepts the state string directly. `state="SETTLED"`, p=0, no thresholds, and a locally available zero residual produced an available row labeled settled without a successful `classify_settling` result. Producers must consume registered physical inputs and a validated settlement result, not caller labels.

## Invented evidence can become qualified, verified, and published

**Confirmed BLOCKING.** `qualification_result` accepts artifact references based on `{artifact_id, version, hash}` shape without resolving their content. A graph with invented references, empty source/calibration data, and one sample returned `AVAILABLE {qualified: true}` for a real IRL40SC209 claim.

`control_axis_status` similarly returned `AVAILABLE/VERIFIED` for a firmware bundle with an empty requirement trace, `deterministic_test_artifact=None`, and one arbitrary true predicate, and for a hardware bundle with empty identity, calibration, conditions, coverage, and limits. `publish` then accepted fabricated semantic values because ATS, conflict, timing/analog, thermal, control, basis, uncertainty, and boundary fields are checked for presence rather than provenance. These decisions must resolve hash-validated content through a trusted registry and derive publication fields from fresh dependencies.

## Freshness can be bypassed with an incomplete dependency registry

**Confirmed HIGH.** `ArtifactRegistry.select_transaction` stales descendants solely from `registry.dependencies`, while `validate_current` checks only hashes embedded directly in the selected result. It never validates graph completeness or consistency with result dependencies. In an `e → a → b → c` chain registered with an empty graph, changing `e` left `c` `FRESH`, and `consume_registered` returned it `AVAILABLE`.

Registry construction must validate a closed dependency DAG and reject missing or extra edges before any transaction or consumption.
